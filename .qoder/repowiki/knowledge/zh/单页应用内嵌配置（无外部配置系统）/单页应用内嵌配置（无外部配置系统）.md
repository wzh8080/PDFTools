## 概览

该仓库是一个纯前端单页应用（`index.html` + `app.js`），**没有后端、没有环境变量、没有配置文件加载器**。所有“配置”都以字面量常量和模块级状态变量的形式直接硬编码在 `app.js` 中，运行时通过 DOM 控件修改这些变量。

## 关键文件与位置

- `manifest.json`：PWA 清单（名称、图标、主题色、语言等），是仓库中唯一的外部结构化配置。
- `app.js`：全部业务逻辑与运行时配置集中在此一个 IIFE 中。
- `lib/pdf-lib.min.js` / `lib/pdf.min.js`：第三方库，非项目自身配置。

## 配置组织方式

1. **全局常量**（不可变）
   - `A4W = 595.276`, `A4H = 841.89`（A4 尺寸 pt）
   - `RENDER_W = 820`（预览 canvas 逻辑宽度）
   - `TRIM_PAD = 3`（白边裁剪留白 pt）
   - `mm2pt = 72 / 25.4`（毫米到点换算）
   - `ROT_MATRIX`：PDF `/Rotate` 的四个变换矩阵映射

2. **可变的运行时状态**（集中在 `state` 对象）
   ```js
   var state = {
     mode: 'auto',       // 'auto' | '2' | '3'
     marginX: 10,        // mm，滑块 0–20
     marginY: 20,        // mm，滑块 0–40
     shift: 0,           // %，栏间偏移
     trim: false         // 是否启用白边裁剪
   };
   ```
   这些值由 `seg-mode`、`margin-x-range`、`margin-y-range`、`shift-range`、`trim-chk` 等 DOM 元素的事件处理器直接赋值。

3. **持久化设置**
   - 仅 `trim` 选项通过 `localStorage` 持久化，键名为 `pdfsplitter.trimWhite`。
   - 读写均包裹 try/catch，以兼容 `file://` 或隐私模式下的拒绝访问。

4. **PWA 元数据**（`manifest.json`）
   - `name`/`short_name`/`description`/`lang` 为中文
   - `display: standalone`，`orientation: portrait`
   - `background_color: #edf1f6`，`theme_color: #2563eb`
   - 三档 icon（any/svg、192x192、512x512）

## 架构约定

- 单一职责文件：`app.js` 同时承担 UI 绑定、PDF 处理、状态管理，不存在独立的 config 模块。
- 默认值就近定义：每个配置项在其首次使用的附近声明（如 `TRIM_KEY` 紧挨着 `localStorage` 读写处）。
- 用户输入即配置：UI 控件的 `value` 直接写入 `state`，没有中间层校验或转换（除 `parseInt(..., 10)` 外）。
- 第三方库通过全局变量接入：`window.pdfjsLib`、`window.PDFLib`、`window.PdfShell`，未使用 import/module 机制。

## 约束与规则

- **无外部配置源**：仓库中没有 `.env`、`.json` 配置（除 PWA manifest）、YAML、INI 等任何外部配置格式；也没有读取 `process.env`、`import.meta.env` 的代码。
- **无构建期替换**：未发现 webpack/vite/esbuild 等构建配置，常量不会被编译期注入。
- **PWA 清单字段完整**：`manifest.json` 包含 name、short_name、description、start_url、scope、display、orientation、background_color、theme_color、lang、icons，遵循 PWA 规范。
- **本地存储容错**：对 `localStorage` 的访问统一用 try/catch 包裹，失败时静默忽略（见 `TRIM_KEY` 两处读写）。
- **文件名约定**：输出 PDF 固定后缀 `_A4切分.pdf`（见 `baseName` + 拼接逻辑）。
