仓库以 `pdf-splitter/`（Web 本体，PWA，含 pdf.js 预览与 pdf-lib 切分逻辑）为唯一业务源；`android/` 通过 Gradle 任务 `:app:syncWebAssets` 在构建时把 `pdf-splitter/` 同步进 `assets/www`，由 `WebViewAssetLoader` 以 `https://app.androidplatform.net/assets/www/` 提供，避免 `file://` 下 worker 加载失败。

- Android 壳仅承担 WebView 无法完成的四件事：系统文件选择器、MediaStore 写入下载目录、FileProvider 分享、阅读器白名单跳转，其余全部走 JS ↔ Java 桥（`PdfShell.save()` / `share()`）。
- `pdftool_test/` 是独立的 Node.js 验证集，用 pdf-lib 复现同样的旋转归一化 + 栏检测 + 嵌入策略，用于对比不同输出效果，不参与 APK 构建。
- `dist/` 存放已签名 APK，被 `.gitignore` 排除；`pdf_preview/` 输出同样不入库。
- 两个关键算法（`/Rotate` 烘焙进 transformationMatrix 的坐标归一化、每栏位图扫描白边）在 Web 与测试脚本中保持一致，作为跨子模块的共享契约。
